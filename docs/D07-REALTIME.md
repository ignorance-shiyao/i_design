# D07 实时滑窗

本次关闭 D07。示例页：`/#/components/realtime`。
开发分支 `cursor/d07-realtime-window-c2d1`。

## 窗口按时间切，迟到的点按事件时间归桶

`packages/common/src/logic/realtime.ts` 的 `buildRealtimeWindow` 是唯一入口。
这张图回答的是「此刻往回看，最近这一段发生了什么」。和留存一样，
最危险的不是算错，而是把「没有数据」画成「数据是 0」。五条口径：

- **窗口按时间切，不按条数切。**「最近 100 条」在尖峰时可能只覆盖 3 秒，
  在低谷时覆盖半小时——同一张图上的横轴含义会跟着密度漂。这里窗口与桶宽
  都是固定时长；条数只限制缓存，不定义窗口。
- **迟到的点按事件时间归桶，不按到达时间。** 14:00:05 发生的事，14:00:20
  才送到，归进 14:00:00 那个桶。归进「当前桶」会在最新位置凭空冒尖峰。
  桶已经滑出缓存的，列为「来得太晚」，不静默丢弃。
- **断流不是 0。** 桶内无点且落在已知断流区间 → 状态 `gap`、值 null，
  折线在这里断开。真正测到的 0 是 `ready` 且值为 0。两者必须能分开。
- **暂停时窗口钉死。** 暂停是「让我看清楚这一段」；窗口继续滑就永远看不清。
  暂停期间到达的点仍按事件时间入缓存；恢复时窗口跳到最新。暂停状态必须可见。
- **乱序按事件时间排；同一 id 只留最后一次。** 缓存到顶从最老那头丢掉，
  被挤掉却本该落在窗内的点同样要报出来。

口径字串跟着模型走，必须显示在图上（「按事件时间归桶……」）。
状态芯片用 `*-subtle` + `*-text`，不用饱和色当正文字色——否则成功色压在
淡底上只有约 2:1，axe 直接判红。

## 验证证据

2026-09-21 实测（Playwright，`CHROMIUM_PATH` 指向 `/opt/pw-browsers/chromium`）：

| 页面 | 视口 | 横向溢出 | 关键量 | 正文最长 |
| --- | --- | --- | --- | --- |
| 实时滑窗 | 1440 / 390 / 320 | 0 / 0 / 0 | 直播 4 桶；断流态 2 个 gap 桶画「—」、折线拆成 2 段 | 45 / 24.43 / 17em |

亮暗两态与断流态 axe serious/critical = 0。图区高度在三个视口下均为 180px，
没有被 SVG 视口压扁。

单测：`realtime.test.ts` 13 条。浏览器故障注入 10 次，每次确认对应用例报红：

- 断流桶画成 0、断流处折线不断开、暂停状态不可见、迟到点明细被吞、
  键盘选中不更新、口径说明被改成「按到达时间」、正文行长超 45em、
  页面横向溢出、暂停未钉住窗口、迟到点被塞进当前窗。

Vite 把 TS/SFC 编成 JS 后再交给浏览器，故障串必须命中编译后的双引号形态；
否则 `route.fulfill` 改不到实际执行源码，检查会假绿。

小程序与 Flutter 仅通过仓库静态检查，没有 SDK/真机运行证据，不标 runtime-verified。
