# 交接说明

给下一个接手这个仓库的人（包括 AI）。读完这一页就能开工，不必翻聊天记录。

本文讲**怎么干活、什么算干完**；`docs/HANDOVER.md` 讲**改哪里**（目录地图、
不能手改的生成物、检查链）。硬性规则在仓库根目录的 `CLAUDE.md`。

---

## 一、先做这三件事

```bash
git clone https://github.com/ignorance-shiyao/i_design.git
cd i_design
npm ci                     # 必须用 ci，不是 install（见下文 .npmrc 那条）
npm run check:parity       # 基线：这一步在干净仓库上必须全绿
```

然后读 **`CLAUDE.md`**（仓库根目录）——硬性规则，违反其中任何一条都算缺陷，
即使构建通过、测试全绿。里面有几条是反直觉的（不用加粗边线表达状态、
元素色不用渐变、实心色块上的字要底色与字色成对取而不是一律白字），先读完再动手。

规模数字不要手数，看按源码生成的 [`SOURCE_STATUS.md`](./SOURCE_STATUS.md)，
它由 `npm run build:docs` 生成、`check:docs` 盯着新鲜度。

## 二、已知的坑，别重复踩

| 坑 | 说明 |
| --- | --- |
| `packages/vue`（Vue 2.7）的类型不能走 vue-tsc | vue-tsc 绑的是 Vue 3 语言服务，拿去编 2.7 会把合法产物报成错。类型由 `packages/vue/scripts/build-types.mjs` 按源码生成；解析器必须把 `Record<string, T>` 里的逗号当成泛型参数，否则 d.ts 会写成非法语法 |
| `.npmrc` 的 `legacy-peer-deps=true` | 不能删。删了 CI 的 `npm ci` 直接失败——Vue 2.7 与 Vue 3 共存是刻意的 |
| 不要用 `cat >` 覆盖已存在的文件 | 出过事故：覆盖 `logic/countdown.ts` 时把整个移动端实现冲掉了，而构建照样绿。先 `cat` 看一眼再决定是改还是加 |
| 生成物不能手改 | 清单见 `docs/HANDOVER.md` 第 3 节。手改的内容下一次构建就没了，且不会报错 |
| 文案不写死 | 所有用户看得见的固定字走 `logic/locale.ts`；组件自己传了优先于字典 |
| 命令式 API 的宿主不在组件树里 | `message()` / `confirm()` / `notification()` 挂在 `document.body` 上，inject / context 到不了那里。给它们接上下文要走 `localeBridge` 那条路，否则接了等于没接，而且看起来像接过了 |
| 中文与中文之间不换行 | 模板里的换行会被压成一个空格，而且真的进了 DOM 文本——复制粘贴带着它，读屏也会读出停顿。要换行就整句写完再换。`check:cjk` 会拦 |
| 一次性脚本不要提交 | `.gitignore` 挡了 `*.tmp.mjs` / `tmp-*.mjs` / 对应的 png。出过一次：随手起名 `tmp-w3.mjs` 从只写 `*.tmp.mjs` 的规则边上漏了进去 |
| 别用管道跑检查 | `npm run check:a11y \| tail` 会把失败的退出码吞掉（管道的退出码来自 `tail`）。有一条 nested-interactive 差点因此漏过去 |

## 三、什么算「干完」

**「构建通过」不等于「能用」。** 一个任务算完成，要同时满足：

1. **`npm run check:parity` 全绿**（它串了十几项检查：跨端一致、生成物新鲜度、
   属性一致、小程序四件套、Flutter golden、中文换行、选型建议、文档快照……）
2. **`npm run typecheck`、`npm test`、`npm run build` 全绿**
3. **`npm run check:a11y`、`check:responsive`、`check:motion` 全绿**（都要真浏览器）。
   第一个的基线是空的，任何一条 serious / critical 都算失败，**不要往基线里加东西**；
   第二个在 390 / 320 两个宽度扫全站，整页能左右拖就算失败；
   第三个查系统的「减少动效」与主题面板开关是不是都真的把动效关掉了
4. **改了界面就用 Playwright 真跑一遍**，亮暗两态 + 窄屏各看一眼。
   不是截图存档，是**量出来**：改了尺寸就量高度，改了动效就量过渡中的位置。
   这个项目里已经有多次「代码看着对、量一下差 4px」的例子
5. **改了依赖就在 `git archive` 出的干净树里验证**
6. **新增组件要各端齐备**（Vue 3 / Vue 2 / React / 小程序 / Flutter），
   覆盖矩阵不得回退
7. **新增共享逻辑要补 golden 断言与单元测试**，两者都不能少：
   golden 保证「各端算得一样」，单元测试保证「算得对」

### 为什么第 4 条不能省

本仓库靠实机验证才发现的问题，随手能列出一串，而它们**构建全都是绿的**：

- Modal 的 watch 没有 `immediate`，命令式对话框挂载时就是打开的，那段逻辑根本不跑——
  Esc 关不掉、背景照样能滚
- Scrollbar 的轨道按「需不需要滚动条」`v-show`，而滑块长度要按轨道高度算，
  轨道不在布局里高度就是 0，于是永远算出「不需要」
- CheckTag 的悬停态特指度压过选中态，鼠标停在已选标签上它会变回未选中的样子
- 代码块的 `<pre>` 里每个 `</span>` 都另起一行，那些换行被原样渲染，
  每行代码后面跟着一个换行加八个空格——行盒高 44px，而行高只有 22px

### 浏览器验证怎么跑

```bash
npm run dev -- --port 5199          # 另开一个终端
# 站点是 hash 路由：http://localhost:5199/#/components/button
```

Playwright 用仓库里已装好的：`chromium.launch({ executablePath: '/opt/pw-browsers/chromium' })`
（自己的机器上就用默认的）。临时脚本放临时目录，不要进仓库。

截图直接拖进 PR 描述，**不要提交进仓库**——GitHub 会托管它们，
而进了 git 历史就删不掉（事后删文件也不会让仓库变小）。

## 四、加一个组件的完整流程

1. `src/components/IXxx.vue` —— Vue 3 是**源**，vue-next 与 vue2 由脚本生成
2. `src/components/index.ts` 加导出
3. `packages/react/src/components/Xxx.tsx` —— React 手写（index 由脚本生成）
4. `packages/miniprogram/src/components/xxx/{index.js,index.wxml}` ——
   另外两个文件由 scaffold 生成。**目录名必须是组件名的 kebab 形式**
   （`IFineTuneCard` → `fine-tune-card`），否则覆盖矩阵会把它判成这一端缺失
5. `packages/flutter/lib/src/components/i_xxx.dart`
6. 样式写一份：`packages/common/src/styles/components/xxx.css`（各端共享），
   并接进 `styles/index.css`——漏接不会报错，只会让界面是裸的
7. 纯逻辑抽到 `packages/common/src/logic/xxx.ts` + Dart 镜像 + golden 断言
8. 文档页 `src/pages/components/XxxPage.vue` + 路由 + `src/data/components.ts`，
   文档页要写「什么时候不该用它」（`check:whennot` 会拦）
9. `npm run check:parity`——它会告诉你还缺哪一端

## 五、评审这件事

如果你是被叫来**审别人的活**的，按这个顺序：

1. 先独立验证，别信 PR 描述：把分支拉下来自己跑第三节那几条
2. **故障注入**：把它新加的检查故意弄坏一处，看是不是真的会红。
   这个项目里出现过「检查加了但永远不会失败」的情况
3. 读它改的生成物：生成物与源码对不上，说明它手改了生成物
4. 一个 PR 只解决一件事。几项混在一起时，只要有一项不合格，
   整个 PR 就都得退回——包括那些本来没问题的
