# G05 OA 第一切片

入口：示例门户中的「OA 审批」。开发时执行
`npx vite --config examples/oa/vite.config.ts examples/oa`，
构建由 `npm run build:examples` 根据应用登记表自动纳入。

本切片演示一张报销申请：提交 → 待审批 → 退回修改 → 原单重新提交 → 通过 → 通知。
可以切换申请人、审批人和只读观察员。人员沿用 `examples/shared` 的固定种子目录。
数据只在当前页面内存中保存，刷新重置，界面对此有明确说明。
本切片不包含真实认证、网络服务、附件、组织多级审批与持久化；不宣称已验证移动运行时。

## 共享边界

- `packages/common/src/logic/oa.ts`：字段和状态契约、角色与状态矩阵、整数金额、
  版本检查、幂等回执、审批历史和通知的原子快照变更、收件人范围内的已读操作。
- `examples/oa/src/App.vue`：将目录、可控时钟与纯事务模型接到现有
  IFormPage、IEntityPicker、IDetailPage、ITaskCenter；只处理输入与渲染适配。
- 未新增库组件。跨端组件覆盖矩阵不变，后续移动工作台可复用同一事务模型。

## 状态与权限

| 动作 | 必须处于的状态 | 可执行身份 | 其他限制 |
| --- | --- | --- | --- |
| 提交新申请 | 无已有申请 | 有申请权限的人 | 标题、用途、金额、审批人必须有效，不能选择自己 |
| 同意 / 退回 | 待审批 | 指定且有审批权限的人 | 禁止自审；退回必须填原因；版本必须一致 |
| 修改并重提 | 已退回 | 原申请人且仍有申请权限 | 单号不变，重新校验字段，版本必须一致 |
| 已通过后写入 | 已通过 | 无 | 终态只读 |
| 查看记录 | 任意 | 演示身份均可读 | 观察员没有写权限 |
| 标记通知已读 | 任意 | 通知收件人 | 不能修改其他身份的通知 |

同一请求标识重发不重复建单或发通知；相同标识换内容返回冲突。
每次成功流转同时追加历史与通知，不会出现状态已变而通知遗漏的半次提交。
申请版本过期时，详情停用写动作；「模拟其他窗口退回」用于复现协作冲突。
刷新到最新版本后，原申请人才能修改并重提。

## 验收与故障注入

共享逻辑有 9 条测试，包含完整流转、幂等、自审、越权、必填原因、
版本冲突、27 种角色/状态/动作组合、收件人隔离、金额精度与重提字段白名单（不允许覆盖申请人、单号和历史）。
`check:e2e` 增加 OA 主流程与版本冲突两条浏览器路径：
从表单操作到最终审批状态、历史记录、正确收件人的通知与同一单号，均验证真实结果。

OA 的表单、已通过详情、通知、列表各在 1440 / 390 / 320 宽度测量，
横向溢出均为 0；各状态同时跑亮暗两态 axe，serious / critical 为 0。
宽屏复用版面审计并采用 45em 行长上限。
本轮实测宽屏正文最长 28em，窄屏最长 22.95em，未发现卡片网格撑高。
三张不同正文长度的卡片在 1440 宽度实测高度为 174 / 245 / 340px，按内容定高；
390 宽度为 190 / 299 / 435px，320 宽度为 190 / 354 / 544px。

新增检查的故障注入修改浏览器实际收到的 JS：
将通知的 recipientId 改坏，收件人通知断言判红；将页面撑至 1800px，溢出断言判红。
另将示例目录从临时副本删除，既有入口检查确认报错，避免继续依赖「OA 还没做」的旧假设。
