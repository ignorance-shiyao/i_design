# H03 视觉、键盘与读屏抽检矩阵

H03 不把「页面能打开」当作通过。自动检查负责扫描全路由，人工抽检负责验证
焦点是否按用户理解的顺序移动、状态变化是否会被读屏说出来，以及截图中的差异是否仍可接受。

## 运行前提

固定 seed、时间、字体、主题和动效开关；检查运行时使用 Playwright Chromium。浏览器路径由
`CHROMIUM_PATH` 指定，CI 必须提供该可执行文件。没有浏览器时，不能生成或更新截图基线，
也不能把 H03 标为完成。

每次运行先执行：

```bash
npm run check:a11y
npm run check:responsive
npm run check:layout
npm run check:motion
```

这四项分别覆盖全路由的 serious/critical axe 违规、390/320 横向溢出与最小 SVG 字号、
1440 正文行长与卡片撑高、系统减少动效与站内动效开关。它们均为零容忍，不能用基线豁免。

## 截图矩阵

| 入口 | 状态 | 主题 / 密度 / 视口 | 目测点 |
| --- | --- | --- | --- |
| `/components/table` | 多级表头、纵向合并、金额排序后合并断开 | 浅/深；默认/紧凑；1440、390 | 表头分组不偏列；合并不跨越小计或层级；窄屏局部滚动不拖整页 |
| `/components/board` | 可落、WIP 满、流转不允许、已归档 | 浅/深；默认；1440、390 | 不可落目标在拿起时有文字理由；列空白仍是落点 |
| `/components/task-center` | 进行中、失败、完成待查看、重复任务 | 浅/深；默认；1440、390 | 角标只计需要处理项；业务对象与任务号始终可见 |
| `/components/form` | 初始、校验失败、服务端错误、离开保护 | 浅/深；默认/紧凑；1440、390 | 错误不只靠颜色；操作区不遮挡字段；窄屏操作不溢出 |
| `/components/thread` | 未读线、删除父评论、发送失败重试 | 浅/深；默认；1440、390 | 未读线固定；删除父评论仍保留上下文；失败原文不丢失 |
| `/lab` | 已注册组件的默认 fixture | 浅/深；默认；1440、390、320 | 所有组件有真实渲染；控件标签与可读字号完整 |

基线截图由具备浏览器的 CI 生成后提交；每次差异需附变更原因、对应组件和实际量测，不接受
「看起来差不多」作为结论。

## 键盘与读屏抽检

| 入口 | 键盘路径 | 通过条件 | 读屏核对 |
| --- | --- | --- | --- |
| 表格 | `Tab` 至表头排序、空格切换选择、`Tab` 至展开 | 排序状态可读；收起不丢选择；焦点不跳到隐藏单元格 | 表头能读出分组与升/降序；复选框说明包含收起行 |
| 看板 | 选中卡片后方向键、`Enter`、`Esc` | 与拖动/菜单得到同一落点；不可落原因可见 | 卡片、泳道、列与变更后的负责人/状态可读 |
| 表单 | `Tab`、`Shift+Tab`、提交、离开 | 首个错误可定位；弹层关闭返回原触发点 | 字段名、帮助、错误关联；离开确认以对话框身份播报 |
| 任务中心 | `Tab`、`Enter` 打开任务或通知 | 失败、待查看、进行中不混淆；通知能定位业务对象 | 任务号、业务对象、状态和恢复动作可读 |
| 评论线程 | `Tab` 至失败消息重试 | 重试原地更新；未读线不会因新消息移动 | 新消息为礼貌播报；删除占位仍说明上下文 |

人工读屏抽检采用系统读屏器，记录系统、浏览器、读屏器版本、入口、操作、实际播报与结论；
自动 axe 通过不替代这一项。

## 故障注入要求

新增任何 H03 自动规则都要同时提交会失败的反例：例如把一个可见焦点样式删掉、把
`aria-describedby` 断开、让 320px 页面出现整页横向溢出，确认检查先红再修绿。仅新增
永远通过的截图或脚本不计入 H03 证据。
