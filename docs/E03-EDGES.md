# E03 端口连线编辑与校验面板

示例页：`/#/components/flow` 的「端口连线与校验面板」。
口径在 `packages/common/src/logic/wiring.ts`，分支 `cursor/e02-node-registry-c2d1`。

## 五条口径

1. **方向按端口的 `side` 判**：出口只能当起点，入口只能当终点。
   不判方向，一张图里会同时存在「A 出 → B 出」这种连法——图上看着正常，
   跑起来才发现走不通。
2. **端口必须真的存在**：指名了 `fromPort` / `toPort` 就要在节点上找得到。
   找不到时不许退回「按节点连」，那会静默改掉这条线的语义。
3. **重复边拒绝**：同一对端口之间的第二条线在图上与第一条重叠，
   看不出是两条，删一条会像没反应。
4. **自环与环按图类型处理，不是一律禁**：状态机与审批流需要自转和驳回回边，
   DAG（依赖、血缘）里一个环就是死循环。所以 `kind` 必须显式给。
5. **类型不匹配要报**：端口写了 `accepts` 就按它收，连线类型给了白名单
   就不许出现白名单外的类型。为此 `GraphPort` 加了可选的 `accepts`——
   往返无损不受影响，它跟着 ports 原样存取。

校验结果是**一串可定位的问题**而不是一个布尔值：每条带 `target`
（`edge:e1` / `node:n1.port:out`），面板点一下就跳过去。一句「连线非法」
等于没说，用户只能一条条试。

同一个环只报一次。环上每条边各报一遍的话，面板上会出现十条说着同一件事的记录。

自环在 DAG 里报的是 `self-loop` 而不是 `cycle`：说「连回自己」比说「成环」
更贴近用户刚做的那个动作。显式放开自环之后，环这条规则照样拦。

重连不做成「先断后连」：中间那一步是一条悬空边，一旦新的一端不合法，
用户手里剩下的是一张比原来更坏的图。要么整条换成新的，要么原图不动。

## 验证证据

2026-09-21 实测（Playwright，`CHROMIUM_PATH` 指向缓存 Chromium）：

| 页面 | 视口 | 横向溢出 | 连线行 | 正文最长 |
| --- | --- | --- | --- | --- |
| 端口连线与校验面板 | 1440 / 390 / 320 | 0 / 0 / 0 | 2 / 2 / 2 | 45 / 22.46 / 17em |

亮暗两态 axe serious/critical = 0；`check:edges` 已接 CI。

单测：`wiring.test.ts` 19 条。浏览器故障注入 8 次，每次确认对应用例报红：

- 重复边不拦、DAG 回边不拦、悬空边不报、问题丢掉 target（面板点了不定位）、
  类型白名单失效、断开不生效、重连把自己算成重复边、校验面板整块失效。

Vite 把 TS/SFC 编成 JS 后再交给浏览器，故障串必须命中编译后的双引号形态。

一个坑记在这儿：示例里那条故障边原先叫 `bad-dangling`，而面板的原因里带着边
id，于是「整段文本里有没有 dangling」这条断言永远成立——故障注入照样报绿。
改成只读 code 那一列，并把 id 换成不含码字的 `loose-1`。**断言要对着结构读，
不要对着整段文本搜关键字。**
