# H04 性能基线

## 这份基线为什么不写毫秒

时间基线在别人的机器上必红。CI 的机器、开发容器、谁的笔记本，快慢差着好几倍；
把毫秒数写进断言，等于交付一条对多数人都是红的检查——而一条对谁都红的检查，
很快就会被当成噪音关掉，比没有检查更糟。

所以自动判定只用**结构性的量**：多少条数据，渲染出多少个节点。它在谁的机器上都一样，
而且恰好覆盖这套库里最值钱、又最容易悄悄消失的东西——虚拟化。
虚拟化被顺手去掉之后，页面照样能用、测试照样绿、截图照样对，只是慢十倍，
而「慢」在开发机的假数据上未必看得出来。

原始时间仍然要记，但它属于**记录**而不是断言：跑 `node scripts/check-perf.mjs --record`，
把当次的数字连同环境贴到下面，供人比对趋势。

## 预算与判定

`npm run check:perf`（判据在 `scripts/check-perf.mjs` 的 `BUDGETS`）：

| 入口 | 数据量 | 渲染节点预算 | 这个预算在拦什么 |
| --- | --- | --- | --- |
| `/components/table` | 20000 行 | ≤ 150 | 虚拟化只渲染视口内那几十行；没有它这里会是两万 |
| `/components/layout` | 20000 项 | ≤ 60 | 同上，列表项更轻、窗口更小 |
| `/components/select` | 10000 项 | ≤ 150 | 下拉打开时只渲染可见的那一屏 |

另有整页元素上限 4000，拦的是「某一页把什么都铺出来了」这种整体性退化。

预算**不是按实测值贴着定的**：贴着定的话，任何一次正常的版面调整都会踩线，
于是预算被一路调高，最后失去意义。这里留了三到四倍余量，它要拦的是数量级的变化。
故障注入里有一条专门钉住这件事：预算既不能贴着实测值，也不能松到虚拟化没了还过得去。

还有一条兜底：**渲染出 0 个节点也算失败**。选择器过期之后一个都匹配不到，
`0 <= 预算` 永远成立，检查会一直绿着而其实什么也没在看。
写这份检查时就先踩了一次——虚拟列表的类名猜错，兜底当场拦住。

## 固定负载：画布与会话列表

`IFlow` 和 `IChatList` 当前不是虚拟化组件。夹具位于 `scripts/perf/`，
只通过 Vite 开发服务器加载，不进入站点构建，也不新增公共组件。
这里的列表指会话列表，不把它称为消息气泡的虚拟化性能。

| 固定输入 | 完整性 | 组件子树元素上限 | 2026-09-19 实测 |
| --- | --- | --- | --- |
| 100 个画布节点、99 条无标签连线，默认缩略图 | 恰好 100 个主画布节点 | 2000 | 642 |
| 1000 条未归档会话，固定长度标题，无置顶 | 恰好 1000 项 | 30000 | 13011 |

完整性约束避免漏画内容换来更小的测量值；总元素预算给当前开销保留两倍以上余量，
拦截固定负载下额外的重复内容。它不限制业务可以传多少数据，也不意味着组件已经支持
无限长列表。数据长度、视口（1440×900）与动效偏好（reduce）都固定。
旧的 4000 元素整页上限仍只用于三条文档入口，不套到千条会话夹具。

`check:perf` 内的真实浏览器测试拦截夹具模块，实际修改浏览器执行的代码：
分别把两种负载减半、翻倍，并分别向组件容器追加 31000 个元素。
六次注入均失败于对应判据；正常版本均通过。
实测错误值：画布 50/200 项、31642 元素；会话 500/2000 项、44011 元素。
测试同时确认源码替换确实发生，避免注入没有命中却报告成功。

## 内存采样协议与记录

运行 `CHROMIUM_PATH=浏览器路径 node scripts/check-perf.mjs --record`。
每种固定负载用独立浏览器 context，先加载一次预热；随后同页重新导航三次，
每次等 Vue 提交并经过一帧，调用 CDP `HeapProfiler.collectGarbage`，
再读取 `Runtime.getHeapUsage.usedSize`。记录三次原始字节值，不取单次峰值。
这是 GC 后 JS heap，不是进程 RSS、GPU 内存或泄漏证明，也没有跨版本硬阈值。
比较趋势时须固定 Chromium、Node、负载与视口；Vite 开发运行时本身也计入堆。

环境：2026-09-19 / Linux x64 / Node v24.19.0 / Chromium 153.0.8010.0。
本机 `/opt/pw-browsers/chromium` 不存在，使用 `CHROMIUM_PATH` 指向缓存浏览器。

| 负载 | 第一次（字节） | 第二次 | 第三次 |
| --- | --- | --- | --- |
| 百节点画布 | 5335284 | 5335340 | 5344740 |
| 千条会话列表 | 30602684 | 30568036 | 30574016 |

同次旧入口测得表格 44 行/1224 元素/3812ms、虚拟列表 11 项/573 元素/508ms、

## 范围边界

这次完成第 10 节指定的画布、会话长列表和内存协议补项；
不声称测量了全部图表类型、真实长消息内容、各端原生内存或交互泄漏。
若增加这些范围，应使用独立固定负载与相应的故障注入。
